# 截图、录制优化与翻译修复记录

## 2026-11-25：动图体积、录制占用与工具栏

本次优先保持画质与采样节奏，主要压缩 GIF / WebP；MP4 使用质量优先的 H.264 VBR（质量 90），不压低原来的分辨率、帧率或码率预算。以下结果来自本机合成界面，不能外推所有照片、视频和硬件编码器。

- GIF 合并连续相同画面并累计延时，变化画面只写变化矩形。先按原方式量化，再保留索引与调色板裁切；与基线相比，合成后的播放画面逐像素一致。超过 16 位延时容量的静止段会拆开写。
- WebP 保留质量参数 80，启用混合有损 / 无损选择与动画体积优化，压缩搜索档位为 2。帧延时按累计时间取整，60 次采样累计为一秒；判重读盘放在后台，准备编码时仍可取消。
- 静止画面复用上一张屏幕快照和 PNG，所有采样记录与时间仍保留；三种编码器复用重复路径，MP4 不再反复解码同一 PNG。变化画面仍重新采集，不合并仅仅相似的内容。
- 工具栏优先靠近选区上方，维持置顶且不抢被录窗口的焦点；左侧手柄可拖动，自动避让选区。停止并保存使用独立按钮，点击空白不会停止；状态区域固定宽度，更新进度不会推走按钮。窄屏自动换行，编码时隐藏暂停、静音与停止按钮。

### 同批画面体积与保存耗时

基线为 `2473c76676fe29c5192320d8c926c3a46ed10290` 的 `FlashTrans.dll`。同进程分别加载两版编码器，共用 **1024×576、24 帧、12 fps** 输入；预热后交替运行三次，耗时取中位数。静态样例完全重复，动态样例每帧改变文字与色块。计时只覆盖编码保存，不包含录制和验证。

| 样例 | 格式 | 修改前 KiB | 修改后 KiB | 体积减少 | 保存耗时：前 → 后 |
| --- | --- | ---: | ---: | ---: | ---: |
| 静态界面 | GIF | 623.8 | 26.0 | 95.8% | 25.0 → 26.0 ms |
| 动态界面 | GIF | 626.6 | 498.2 | 20.5% | 186.3 → 235.8 ms |
| 静态界面 | WebP | 81.8 | 3.3 | 95.9% | 91.4 → 122.1 ms |
| 动态界面 | WebP | 1721.3 | 73.6 | 95.7% | 944.8 → 2418.1 ms |
| 静态界面 | MP4 | 201.5 | 91.1 | 54.8% | 1436.8 → 1213.7 ms |
| 动态界面 | MP4 | 207.2 | 98.8 | 52.3% | 1227.7 → 1189.8 ms |

GIF 两组的合成画面均与基线逐像素一致，累计播放时长仍为两秒。WebP 两组首帧均与源图像素一致，原版首帧 PSNR 为 42.33 / 41.86 dB。MP4 首帧 PSNR 从 34.61 / 34.59 dB 提升到 44.03 / 44.03 dB；只测了这两个样例的首帧，不代表所有内容无损。

GIF 和 WebP 的保存阶段多做了压缩计算，动态 WebP 本机样例约由 0.94 秒增至 2.42 秒。这项开销发生在停止录制后；不能把采集端减少分配和写盘表述成所有阶段 CPU 都更低。

## 2026-10-20：此前优化记录

日期：2026-10-20。以下是本机实测，不是所有电脑、所有录屏内容的性能承诺。

## 改动范围

### 长截图清晰预览

- 以原始物理像素 100% 预览，避免 125% / 150% 等系统缩放再把图片整体放大一遍。
- 将超长图分成高度不超过 1024 像素的分片，虚拟化创建可见位图，避免整张超高纹理被降采样，也不额外缓存整张长图的预览副本。
- 均分末片余量，避免最后一片过短使 WPF 错估虚拟滚动范围。
- 提供原始大小、适应宽度、放大、缩小、Ctrl+滚轮和 Ctrl+0；窄窗口操作栏可换行。
- 所有缩放只影响预览。采集、拼接、复制及 PNG 保存仍使用原始像素，没有伪造锐化、超分辨率或有损重编码。

### 动图保存速度

- GIF 使用有界并行量化与编码，按输入顺序写出；按 CPU 和像素量估算并行工作集，4K / 8K 大帧自动退到单路，避免同时解码整段录制。
- GIF 对逐字节相同的连续 PNG 复用已编码结果，但仍逐帧写入延时和图像块，不丢帧、不加速回放。
- WebP 仅合并逐字节相同的连续帧，并累计停留时间；不同画面和非连续的同一画面不会被错误合并。
- WebP 保持质量参数 80、原始分辨率和时间轴，将压缩搜索档位由默认 4 调为 1，减少为压缩体积所做的计算。
- GIF / WebP 先写独立临时文件，成功后才替换目标文件；失败和取消不覆盖旧文件。取消 WebP 时等待自己的编码进程退出，再清理半成品。

### 同批交付的翻译修复

- 多目标翻译必须覆盖全部目标语言才算成功；部分失败会提示缺失语言并走自动降级，已有译文仍可显示、复制和缓存。
- 翻译源的模型、提示词、地址和密钥等发生变更时使旧缓存失效，并阻止在途旧请求回写。外观变更、选项重排不误清缓存。
- 配置签名使用长度前缀，避免提示词里的分隔符使两套配置碰撞。
- AI 流正常结束却没有译文时进入普通重试和降级链；用户取消不重试，关闭降级后的错误状态不保留上一条可复制译文。
