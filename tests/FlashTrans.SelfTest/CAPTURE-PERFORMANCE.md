# 截图、录制优化与翻译修复记录

日期：2026-10-20。以下是本机实测，不是所有电脑、所有录屏内容的性能承诺。

## 改动范围

### 长截图清晰预览

- 以原始物理像素 100% 预览，避免 125% / 150% 等系统缩放再把图片整体放大一遍。
- 将超长图分成高度不超过 1024 像素的分片，虚拟化创建可见位图，避免整张超高纹理被降采样，也不额外缓存整张长图的预览副本。
- 均分末片余量，避免最后一片过短使 WPF 错估虚拟滚动范围。
- 提供原始大小、适应宽度、放大、缩小、Ctrl+滚轮和 Ctrl+0；窄窗口操作栏可换行。
- 所有缩放只影响预览。采集、拼接、复制及 PNG 保存仍使用原始像素，没有伪造锐化、超分辨率或有损重编码。

### 动图保存速度

- GIF 使用有界并行量化与编码，按输入顺序写出；按 CPU 和像素量估算并行工作集，4K / 8K 大帧自动退到单路，避免同时解码整段录制。
- GIF 对逐字节相同的连续 PNG 复用已编码结果，但仍逐帧写入延时和图像块，不丢帧、不加速回放。
- WebP 仅合并逐字节相同的连续帧，并累计停留时间；不同画面和非连续的同一画面不会被错误合并。
- WebP 保持质量参数 80、原始分辨率和时间轴，将压缩搜索档位由默认 4 调为 1，减少为压缩体积所做的计算。
- GIF / WebP 先写独立临时文件，成功后才替换目标文件；失败和取消不覆盖旧文件。取消 WebP 时等待自己的编码进程退出，再清理半成品。

### 同批交付的翻译修复

- 多目标翻译必须覆盖全部目标语言才算成功；部分失败会提示缺失语言并走自动降级，已有译文仍可显示、复制和缓存。
- 翻译源的模型、提示词、地址和密钥等发生变更时使旧缓存失效，并阻止在途旧请求回写。外观变更、选项重排不误清缓存。
- 配置签名使用长度前缀，避免提示词里的分隔符使两套配置碰撞。
- AI 流正常结束却没有译文时进入普通重试和降级链；用户取消不重试，关闭降级后的错误状态不保留上一条可复制译文。

## 编码速度对照

环境为 Windows、.NET SDK 9.0.308，使用仓库现有的 WPF/WIC 和 img2webp。基线编码器来自 `ef94749ba09ed103dbb08cb47f7606765e69ad12`。

两版编码器在同一个自测进程中加载，共用同一组 PNG 输入；双方先预热，再交替运行三次，取中位数。每组均为 **1024×576、24 帧、目标 12 fps**。静态样例是完整重复的合成界面；动态样例逐帧改变文本和标记。样例不读取用户窗口。

计时覆盖 `SaveAsync` 的编码与写文件，不包含录制、样例生成和解码验证。

| 静态界面 | GIF | 468.8 ms | 23.5 ms | 19.95 倍 |
| 动态界面 | GIF | 467.8 ms | 183.1 ms | 2.55 倍 |

### 质量与体积边界

- 两组 GIF 均验证了优化前后文件**逐字节一致**，不仅是帧数和大小一致。
- 两组 GIF 均为 24 帧，累计延时 200 厘秒；WebP 的重复帧合并另有实际容器测试，验证停留时间累计和无限循环标记。
- WebP 压缩搜索减少后，本次样例文件增大约 **26.2%～30.7%**，属于用一定文件体积换取保存速度，不是降低分辨率或丢弃变化画面。
- WebP 首帧对原图的 RGB PSNR：静态样例 41.31 → 42.33 dB，动态样例 41.02 → 41.86 dB。这只验证两个合成样例的首帧，不能外推所有帧、照片或视频内容。

- Release 主程序和自测工程构建通过，0 警告、0 错误。
- 长截图专项覆盖 100% / 125% / 150% / 200% DPI 的尺寸规则，以及本机 125% DPI 下的真实窗口布局。
- 513×40017 超长图验证可见分片虚拟化、滚到底、缩放、窄窗口和原像素恢复；分片逐字节对照源图。
- 257×17001 PNG 保存后解码，尺寸和全部像素与源图完全一致。
- 真实显示可滚动 WPF 内容，通过 GDI 实际抓屏并调用长截图拼接链路；结果尺寸和全部像素与参考页面一致。
- 录制专项验证 GIF / WebP / MP4 的帧序、方向、帧率、延时、循环、暂停、丢弃、损坏输入、旧文件保护和半成品清理；观察到真实 WebP 子进程启动后取消，确认它已退出。
- 翻译专项 20 项通过，使用本机模拟 HTTP / SSE 和真实 WPF 流程，不调用外部翻译接口。
- 最终完整自测共 263 项：**262 项通过，1 项失败**，退出码 1，未启用联网翻译测试。

## 复现入口

先构建当前自测，构建失败时停止，不运行旧 DLL：

```powershell
dotnet build .\tests\FlashTrans.SelfTest\FlashTrans.SelfTest.csproj -c Release --nologo
if ($LASTEXITCODE -ne 0) { throw '自测构建失败' }
$selfTest = '.\tests\FlashTrans.SelfTest\bin\Release\net9.0-windows10.0.19041.0\FlashTrans.SelfTest.dll'
dotnet $selfTest --only-longshot
dotnet $selfTest --only-record
dotnet $selfTest --only-translation
dotnet $selfTest --record-benchmark
dotnet $selfTest
```

同进程前后对照在 `--record-benchmark` 后添加 `--baseline-assembly` 和修改前 `FlashTrans.dll` 的绝对路径；该 DLL 需要单独从上述基线源码构建。当前编码器与基线编码器在不同的程序集加载上下文中运行，不覆盖正在使用的程序或 DLL。

完整自测会显示临时窗口并操作剪贴板、截图和录制，应在桌面可用且不进行其他操作时运行。不加 `--net` 或 `--ocr-corpus`。
